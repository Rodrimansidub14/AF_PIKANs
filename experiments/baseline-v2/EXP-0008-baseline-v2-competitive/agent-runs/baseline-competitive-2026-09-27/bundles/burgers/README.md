# Burgers: RBF fijo frente a PINNacle Vanilla — paquete candidato

Paquete revisable offline para cinco pares de seeds 811–815 en Kaggle `NvidiaTeslaT4`, con preflight que exige dos dispositivos CUDA visibles. Dos parejas se entrenan concurrentemente; dentro de cada pareja, RBF y Vanilla usan secuencialmente la misma pool Sobol. Cada brazo usa Adam 1e-3, float64, hasta 20,000 updates o 900 device-s. Vanilla es MLP tanh 5×100, sin L-BFGS.

La métrica primaria es `field_relative_l2` contra Cole–Hopf/Gauss–Hermite de orden 128 en la malla 1025×129. Un scorer Torch independiente ejecuta referencia, derivadas, residuales y métricas en CUDA; CPU solo carga checkpoints y serializa resultados. Puntúa únicamente los diez checkpoints finales tras completar las cinco parejas. Cada wave puntúa dos brazos concurrentemente, con un cap de 90 s; el máximo asignado es 450 s de pared y 900 device-s. El timeout es finito; si se rebasa, la campaña queda incompleta. El número publicado PINNacle es contextual por su referencia FEM discreta.

El cap total es **7,200 s de sesión/cuota Kaggle**. La aritmética de peor caso es 300 s de startup previo a la primera celda + 300 setup + 240 smoke + 5,760 entrenamiento/proceso + 450 puntuación final + 90 escritura de artefactos + 60 cierre = 7,200 s. El watchdog interno dura 6,900 s desde la primera celda, más el margen de cierre; el push debe usar un hard timeout de 7,200 s. Presupuesto agregado: 10,740 device-s de un cap propuesto de 14,400 (9,000 training + 240 smoke + 600 proceso/telemetría + 900 scoring); quedan 3,660 device-s sin asignar. Son límites, no tiempos medidos.

**Diferencias del contrato:** el trainer Torch-only usa minibatches con reemplazo sobre las pools, y no implementa el loader PINA/Lightning del paper. Esta adaptación no es reproducción literal del tutorial. No se instala nada por `pip`; el paquete requiere Torch, NumPy y SciPy preinstalados. El scorer y su fórmula Cole–Hopf CUDA están marcados `DRAFT_UNVERIFIED` porque no se ejecutaron.

**Estado: DRAFT_UNVERIFIED; la fase confirmatoria no ha empezado.** El presupuesto de 7,200 s y la ejecución remota fueron autorizados; `scientific_accepted=false` y `scientific_preregistration_signed=false`. La versión remota 5 alcanzó el smoke de GPU, guardó el checkpoint RBF de seed 811 y expiró el proceso a los 240 s antes de completar el brazo Vanilla; no arrancó la campaña de cinco pares ni produjo scores confirmatorios. Este paquete reduce el smoke a 60 GPU-s por brazo y conserva el cap de pared de 240 s y el de sesión de 7,200 s. No se corrieron tests, validadores ni entrenamiento local.
