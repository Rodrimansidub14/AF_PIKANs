# Offline build notes and limits

**DRAFT_UNVERIFIED.** The package builder only copies source snapshots, embeds code in a notebook, writes metadata, and computes hashes. It does not import the training modules, inspect Kaggle credentials, upload, execute, preflight, or train. No `approval.json` was created.

The notebook is self-contained with Kaggle-preinstalled Torch and NumPy. It creates one Torch scrambled-Sobol pool per seed and passes the same NPZ path to every arm. Two subprocesses receive distinct `CUDA_VISIBLE_DEVICES` values; each child uses its visible `cuda:0`, which maps to one of the two physical T4s. The notebook records synchronized training and CUDA score seconds separately from session wall/quota hours. No `pip install` or network access is requested.

The numerical scorer builds the development grid and its trapezoidal weights on CUDA, calculates field/traces/energy/residual metrics on CUDA, and copies arrays to CPU only to write artifacts. The 512×256 confirmation grid is generated by `heat_final_eval.py` in a separate post-training subprocess, after all training runs end. Training code never reads that grid. Its score is not used for selection.

H-RBF/H-BS use a verbatim static snapshot of `src/research_pipeline/sciml/model.py` but a new full-batch Torch loop. The pool generator is PyTorch Sobol, unlike historical SciPy/PINA, and batching differs from the previous mini-batch-1024 manifests. Their historical runs cannot be silently pooled with this cohort.

H-FNN retains tutorial layer widths `[2,20,20,20,1]`, tanh, Xavier-normal weights, Adam `1e-3` to 20,000 updates, and L-BFGS only after all Adam updates complete. It is an explicit PyTorch port. The tutorial's soft IC/BC loss is changed to the shared exact hard transform; `alpha`, pool, precision, residual scaling, and development/confirmation grids are adapted. This is not DeepXDE execution, literal reproduction, or a published-paper score.

Remaining blockers are operational, not hidden validation results:

- The Kaggle T4x2 runtime must expose two T4 CUDA devices; this has not been checked remotely.
- CUDA training/scoring speed, memory use, PyTorch Sobol reproducibility in the hosted image, and the number of completed Adam/L-BFGS updates are unknown because no preflight or training was run.
- The schedule reserves 300 seconds for Kaggle startup before the first notebook cell; the cell watchdog is 6,900 seconds with a 60-second close margin, and the Kaggle CLI hard timeout must be 7,200 seconds. It budgets 480 seconds for CUDA development scoring, 20 for smoke finite checks, 960 for the post-training CUDA 512×256 confirmation score, and 40 for artifact flush. Finite wave guards record an incomplete result if a scoring allowance is exceeded.
- The prior standalone `adapters/heat_deepxde.py` still requires DeepXDE and is deliberately excluded from this no-install notebook.
- The preregistered 10% non-inferiority margin is not signed here; it cannot be presented as a universal SOTA threshold.

The current review bundle is not approved for upload. Its target is Kaggle machine shape `NvidiaTeslaT4` (T4×2), as described in [Kaggle's official metadata documentation](https://github.com/Kaggle/kaggle-cli/blob/main/docs/kernels_metadata.md). No tests, validators, local training, Kaggle calls, or remote execution were performed for this build.
