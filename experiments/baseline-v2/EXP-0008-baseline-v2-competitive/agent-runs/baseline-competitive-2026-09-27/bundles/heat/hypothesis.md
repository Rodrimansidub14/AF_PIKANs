# Heat cohort and decision boundary

**Status: proposal for review; no scores or runs exist.** The paired cohort contains H-RBF, H-BS, and H-FNN for seeds `901–905`. H-FNN is a plain-PyTorch port of the published DeepXDE Heat tutorial's `FNN [2,20,20,20,1]`, tanh activation, Glorot-normal initialization, Adam (10^{-3}) to 20,000 updates, followed by L-BFGS only if all Adam updates finish before its 600-device-second cap. It is not DeepXDE library execution or a reproduction of the paper/tutorial.

The common equation is `u_t=0.1u_xx`, `x,t∈[0,1]`, initial field `sin(pi*x)`, and zero spatial boundaries. Each seed has one fixed pool generated using preinstalled `torch.quasirandom.SobolEngine`: 4,096 interior points, 1,024 initial points, and 512 points on each spatial boundary. The same persisted NPZ and SHA-256 are used by all three arms for a seed. The pool stream seeds are `10*seed+1`, `+3`, and `+4`. These new PyTorch Sobol pools are not byte-matched to the historical SciPy/PINA pools.

All arms use float64, the same hard exact trace `u=sin(pi*x)+t*x*(1-x)*raw(x,t)`, and the same full-pool loss `mean(((u_t-0.1*u_xx)/1.1)^2)`. H-RBF and H-BS use a static snapshot of the AF model definitions in a new full-batch Torch loop, not the historical PINA campaign runner or its minibatch-1024 schedule. The hard trace also changes the published DeepXDE tutorial's soft PointSetBC objective. These choices produce a matched AF-adapted pilot and prevent a literal-paper-reproduction claim.

Tier2 uses 600 GPU-device seconds per arm/seed; the five seeds are run under the same two-T4 campaign session. Checkpoints target `120/300/600` device seconds. The separate smoke seed is `900`, at 120 device seconds per arm, and only checks finite outputs and logging. Smoke does not compute quality metrics or filter methods. Development scoring uses the common `257×129` grid on CUDA. After every trainer exits, a separate CUDA scorer generates and scores the confirmation `512×256` grid; training never receives that grid and those scores cannot select a method. Both evaluation stages count toward session wall-time and device-second accounting.

The confirmatory metric is reserved for a separate authorized scoring step. The proposal is to compare paired field relative-L2 values using the five seedwise log ratios `log(L2(H-RBF)/L2(H-FNN))`, report every seed, a paired mean, and a paired bootstrap interval. The internal non-inferiority margin of 10% remains a proposed rule requiring an explicit signature before any result interpretation; it is not a universal SOTA threshold. H-BS is a structural control, not an external literature baseline. Five seeds support a pilot only.

Any non-finite, truncated, over-cap, or contract-deviating run remains in the ledger with its actual cost and failure state; no seed is replaced after scores are visible. Historical cohorts remain contextual until audited for code, pool, loss, precision, optimizer, time accounting, reference, and scoring equivalence.
